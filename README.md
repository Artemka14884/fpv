# DRONE DEFENSE

3D-игра на Three.js + cannon-es (реалистичная физика полёта дрона и оружия),
с онлайн-чатом, никнеймами и синхронным раундом на 10 минут.

**Важно про геймдизайн:** цели дрона — это только объекты обороны базы
(радар, склад топлива, узел связи, депо) и зенитные турели, а не люди.
Роль «Человек» — оборона базы: нужно поднять оружие (клавиша E у ящика)
и сбивать вражеские дроны до того, как они разбомбят постройки.

## Управление

### Человек
- WASD — движение, мышь — обзор, Space — прыжок
- E — поднять оружие у ящика
- ЛКМ — стрельба, R — перезарядка
- Enter — открыть чат, Esc — закрыть

### Дрон (FPV)
- Мышь — обзор/направление полёта (yaw + pitch)
- W/A/S/D — лететь вперёд/влево/назад/вправо относительно направления взгляда
- Shift / Space — вверх, Ctrl / C — вниз, Q/E — доворот корпуса
- B — сбросить бомбу по цели
- 3–5 попаданий турели по дрону = взрыв и респавн

Дрон физически инерционный (масса, разгон, затухание скорости — drag), но
ориентация управляется напрямую мышью, а не полным 6DOF через torque — так
он реально управляем и не срывается в штопор, при этом сохраняет ощущение
настоящего полёта (разгон/торможение, зависание, инерция).

Карта теперь включает открытые поля, густой лес (часть деревьев — плотные,
за ними можно физически спрятаться), заброшенные здания-руины и два больших
завода с трубами — всё это, кроме мелких деревьев, имеет коллизию: игрок
за ними не проходит и может использовать как укрытие.

Раунд идёт 10 минут, синхронно у всех игроков на сервере. По истечении
времени карта пересобирается заново (новый seed), появляется экран
«Матч окончен» с обратным отсчётом, дальше — новый раунд или выход в меню.

## Локальный запуск

```bash
npm install
npm start
```

Открой `http://localhost:3000`.

## Деплой на Render.com

1. Залей эту папку в git-репозиторий (GitHub/GitLab).
2. На Render.com: **New → Web Service**, подключи репозиторий.
3. Настройки сборки:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Environment:** Node
   - Render сам подставит переменную `PORT` — сервер уже её слушает
     (`process.env.PORT`), ничего менять не нужно.
4. Нажми **Create Web Service** — после деплоя игра будет доступна
   по адресу вида `https://<твой-сервис>.onrender.com`, и все игроки,
   зашедшие по этой ссылке, попадут в общий чат/лобби и синхронный
   таймер раунда.

### Важное ограничение (честно предупреждаю)
Полная серверная синхронизация физики (когда сервер — единственный
источник истины для позиций всех дронов и пуль) в этом прототипе не
реализована — это отдельный большой пласт работы (античит, интерполяция,
lag-compensation). Сейчас через сервер синхронизируются: чат, никнеймы,
список онлайн-игроков и общий таймер/сид карты. Каждый клиент считает
физику локально. Для честного соревновательного мультиплеера это стоит
доработать до server-authoritative модели — могу помочь, если понадобится.
